# Release

Ты выполняешь финализацию готовой фичи.

## Preconditions

Сначала прочитай:

docs/ai/features/<feature-name>/review.md

Если там нет:

Status: PASS

остановись.

Не исправляй код.

Не создавай commit.

## Проверка

Прочитай:

- docs/ai/features/<feature-name>/plan.md;
- docs/ai/features/<feature-name>/review.md;
- git status;
- git diff.

Не проводи полный повторный анализ проекта.

Проверь только фактические изменения текущей фичи.

## Документация

Обнови:

docs/ROADMAP.md

Синхронизируй его с фактическим состоянием проекта.

Отмечай задачу выполненной только если она действительно реализована.

Не добавляй неподтверждённую информацию.

Если изменились:

- команды запуска;
- архитектура;
- API;
- структура проекта;
- пользовательские возможности;

и это отражено в README.md, обнови README.md.

Не редактируй документацию, не связанную с фичей.

## Финальные проверки

Проверь:

- нет debug-кода;
- нет TODO, оставленных случайно;
- нет секретов;
- нет .env;
- нет временных файлов;
- нет unrelated changes;
- документация соответствует коду;
- review имеет Status: PASS.

## Git

Выполни:

git status

git diff

Убедись, что в commit попадут только изменения текущей фичи и необходимые изменения документации.

Не добавляй:

- секреты;
- .env;
- IDE files;
- временные файлы;
- unrelated changes.

Создай один Git commit.

Commit message должен быть кратким и отражать фичу.

Пример:

feat(shelves): add user book shelves

## После commit

Проверь:

git status

Сообщи:

- commit hash;
- commit message;
- какие документы изменены;
- итоговый статус.

Ты единственный агент pipeline, которому разрешено создавать Git commit.
